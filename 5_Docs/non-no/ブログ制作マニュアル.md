# non-no大学生エディターズ ブログ制作マニュアル

参考: `/Users/aoi/Desktop/Bluenote/Clippings/nonno/` 配下の過去記事（あおの名義 / トピック記事）から、タイトル・構成・文体・装飾・必須情報・WordPress入稿までを整理したマニュアル。

---

## 0. このマニュアルの使い方

- 新規記事を書くときは **§1 → §3 → §5** をテンプレとして流用し、**§4の文体ルール** に沿って書く。
- 入稿時は **§7 WordPress入稿フロー** と **§8 公開前チェックリスト** を必ず確認。
- 「迷ったら過去記事を真似る」が原則。特に **あおの名義の体験レポ系**（ハリポタショップ、アマムダコタン、3coinsネイル）が型の見本。

## 1. 記事タイプ別テンプレート

non-no大学生エディターズの記事は、用途別に大きく7パターンに分類できる。新規記事は必ずどれかに当てはめて構成を決める。

| # | タイプ | 代表例 | 主な構成要素 |
|---|------|--------|-----|
| A | **完全ガイド型** | ハリポタショップ原宿店、ハリポタスタジオツアー攻略 | アクセス→予約方法→エリア紹介→注意点→まとめ |
| B | **商品レビュー型** | 3coinsマグネットジェル、アマムダコタン | 商品概要→使用方法→使用感→正直レポ→まとめ |
| C | **おすすめスポット紹介型** | 三軒茶屋グルメ、ロンドンお得旅 | 店舗1→店舗2→…→マップ/一覧 |
| D | **イベントレポ型** | 櫻坂46展覧会、新入生応援フェス | エリア/コーナーごとに見出し→お土産→まとめ |
| E | **マイバッグ／ベストバイ型** | バッグの中身、ベストバイ2023 | アイテム単位の見出し→詳細スペック→使用シーン |
| F | **Q&A・OB訪問型** | 広告業界2年目リアル、就活体験記 | プロフィール→1日の流れ→Q&A |
| G | **LOOKBOOK・コーデ型** | 7daysコーデ、オフィスカジュアル | Day1→Day7、または着回し別ブロック |

> 記事を書く前に「これはA〜Gのどれか？」を必ず決める。タイプによって**見出しの粒度・画像の枚数・必須情報**が変わる。

## 2. タイトルの作り方

### 2-1. 基本フォーマット

```
【○○】+ 本題（具体的な対象） + アクション語
```

- **【】の冒頭ワード** が読者の目を止める。検索キーワードも兼ねる。
- 後ろに「紹介」「徹底紹介」「レビュー」「レポート」「攻略」「ガイド」など **アクション語** を必ず置く。
- 末尾には `| No.046 あおの | 大学生エディターズ` のような **担当者識別** を WP のタイトルパターンに従って付ける（WP上で自動付与の場合は本文タイトルからは省略可）。

### 2-2. 冒頭ワード（【】内）の頻出パターン

| ジャンル | パターン例 |
|---|---|
| ガイド系 | 【完全ガイド】【完全攻略】【保存版】【○○最新】 |
| レビュー系 | 【辛口レビュー⁉】【正直レポ】【超人気店】【話題沸騰】 |
| 体験系 | 【マイバック】【LOOKBOOK】【OB訪問】 |
| 価格・スペック系 | 【500円で完成】【無料＆30分で完成】【26ブランド網羅】【100選】 |
| イベント系 | 【ネタバレ注意!】【数量限定】【春休みは○○へ！①】 |
| コラボ系 | 【ジャニーズ×三軒茶屋】【GU×ハリーポッター】 |

### 2-3. タイトルの癖

- **数字を入れる**: 「10選」「26ブランド」「7days」「100選」「500円」「30分」
- **！ ⁉ ？ を躊躇なく使う**: 「徹底紹介！」「話題沸騰⁉」
- **対象を絞る形容詞**: 「超人気店」「話題の」「日本初」「最新」「完全」
- **連載は①②**: シリーズ化する場合は `①` を末尾に付け、次回予告で②に繋ぐ
- **NG**: 抽象語だけ（「便利グッズ紹介」など） / 主語がぼやけるもの

### 2-4. タイトル文字数

- WordPress上で見切れない範囲で **30〜45文字** 目安。
- SNSシェア時のOGP表示を意識して、最重要キーワードは前半30文字以内に。
- **Google検索結果は約32文字で見切れる**ため、メインキーワードは前半20文字以内が理想。
- SEO観点の詳細は §13-3 を参照。

## 3. 記事の標準構成（テンプレート）

すべてのタイプで使える「ベース構成」。記事タイプによってブロックを足し引きする。

### 3-1. ベース構成

```
[アイキャッチ画像]

カテゴリ表示 (ファッション部 / ビューティー部 / グルメ＆ライフ部 / エンタメ部)

No.046 あおの

## [タイトルと同じH2]

[公開日] 更新日：[更新日]

[リード文：3〜5行]

Index (目次)
1. [見出し1]
2. [見出し2]
...

> ## [セクション1見出し]
[本文]

> ## [セクション2見出し]
[本文]

...

> ## まとめ
Point
> ① ○○
> ② ○○
> ③ ○○

[次回予告 / 締めの一文]

[プロフィール枠 — WPテンプレで自動表示]
```

### 3-2. リード文（冒頭の3〜5行）

**役割**: 「何を」「誰向けに」「読むと何が得られるか」を3行で示し、最後に **読了の動機付け** を一文添える。

**頻出パターン**:

```
[トピックの背景紹介。1〜2行]
今回は[何を]を[どう紹介する]していきます！
これを読めば、[読了後のベネフィット]間違いなし！
```

**実例（ハリポタショップ原宿店）**:
> 「ハリー・ポッター」シリーズの日本初旗艦店「ハリー・ポッター ショップ 原宿」が2025年8月14日(木)にオープン！
> 今回は大人気なショップのエリア紹介から、予約〜当日で「当日並べず入れる予約方法」「お店までのアクセス」など、実際レポを基に事前に知っておきたい情報をまとめてみました。
> これを読めば、安心して準備できること間違いなし！

### 3-3. 目次（Index）

- **5項目以上**のセクションがある記事には必ず Index ブロックを設置。
- 数字付きリスト + アンカーリンクで生成。WPプラグイン（Table of Contents Plus 等）で自動生成可能。
- 5項目未満の短い記事では省略可。

### 3-4. 見出しの使い分け

| レベル | 使い方 | 装飾 |
|---|---|---|
| H2（##） | 大セクション。`> ##` のように **引用記号付きH2** にして強調する慣習あり | 太字＋アンダーライン |
| H3（###） | サブセクション。商品名・色名・トピック細分 | 太字 |
| H4（####） | プロフィール枠などWP内専用。本文ではほぼ使わない | — |

- **見出しの命名**: 「①○○」「【正直レポ①】○○」のように **絵文字・記号・番号を頭に付ける** ことで視認性UP。

### 3-5. 商品情報の定型フォーマット（Bタイプ／Eタイプ必須）

```
商品名：マグネットスティックネイルジェル
価格：各330円（税込）

【POINT】
・[特長1]
・[特長2]
・[特長3]

【色展開】
01 [色名]
02 [色名]
...
```

または、ファッション系の場合:

```
[商品名 / ブランド名]
サイズ：W30×H45×D15 cm
容量：20リットル
購入時価格：¥6,900

[補足コメント1〜2行]
```

### 3-6. 評価表（Bタイプ：レビュー型でよく使う）

```
味     ★★★★☆
食べ応え ★★★★★
```

- 5段階。基準は「**3が普通、4がおすすめ、5が殿堂入り**」程度の温度感。
- 辛口レビューでも **総合は★3〜4に着地** させる（★1〜2はほぼ使わない）。

### 3-7. 正直レポ／注意点ブロック

「正直レポ」「ここだけは抑えて」など、**読者目線の本音情報** をブロック化する。

```
## 【正直レポ①】ラメの消えやすさ
[画像]
【正直レポ①】
ラメが思ったより消えやすい？
[具体的な検証結果。2〜4行]
[読者へのアドバイス]
```

### 3-8. 店舗・施設情報の必須項目

物理的な場所に行く系（ガイド型・グルメ系）では、以下を **必ず** 記載:

- 住所
- 営業時間（年中無休 / 定休日）
- 最寄り駅と徒歩分数
- 電話番号（あれば）
- 予約方法（オンライン / 電話 / 当日券）
- 公式URL（テキストリンク）
- 駐車場の有無（車来店想定の場合）

### 3-9. まとめセクション

```
> ## まとめ

Point
> ① [一番伝えたいポイント]
> ② [次に重要なポイント]
> ③ [補足ポイント]
> ④ [注意点]

[締めの一文。読了後のアクションを促す or 次回予告]
```

**締めフレーズの定番**:
- 「次回は○○を紹介するのでお楽しみに！」
- 「気になる方は是非足を運んでみてください(^^)/」
- 「未だ人気が続くバズコスメなので店頭で見かけた方はお早めにお買い求め下さい♪」

## 4. 文体・トーンのルール（最重要）

過去記事から抽出した「あおの／non-noエディターズらしさ」を構成する文体の癖。**ここを外すと一気に他媒体の記事に見える**ので厳守。

### 4-1. 基本トーン

- **ですます調** が基本。常体（〜だ／〜である）は導入の補足説明や引用だけに限定。
- **一人称は「私」**。たまに省略してOK。「筆者」は使わない。
- 読者への呼びかけは「**みなさん**」「**○○な方**」「**○○したい人**」など。「あなた」はやや距離があるので限定的に使う。
- ノリは「**仲のいい先輩女子大生がInstagramでレポしてる**」くらいの距離感。フランクすぎず、丁寧すぎず。

### 4-2. 語尾の癖（コピペで使える定番フレーズ集）

- 「〜していきます！」「〜紹介していきます！」
- 「〜してみました」「〜してみてください」
- 「〜してみてはいかがでしょうか？」
- 「〜してみてね」「〜してみよう！」（カジュアル寄せ）
- 「〜のでお楽しみに！」
- 「〜要チェック！」「〜要チェックです」
- 「〜のでおすすめです」「〜がおすすめ！」
- 「〜間違いなし！」
- 「〜してみるのもありですね」
- 「〜してみるのが個人的にはいいかなと思いました」

### 4-3. 接続詞・副詞の癖

- **頻出語**: 「実は」「ちなみに」「個人的には」「正直」「やっぱり」「結構」「めっちゃ」
- **「実は〜なんです」**: 意外性のある情報を出すときの定番枕詞
- **「ちなみに〜」**: 補足情報を差し込むときの定番
- **「個人的には〜」「正直〜」**: 主観を出すとき、断定を和らげる

### 4-4. 記号・絵文字・顔文字の使い方

| 種類 | 使用例 | 頻度 |
|---|---|---|
| ！ | 「〜です！」「〜！」 | 多用OK（1段落1〜2回） |
| ？ ⁉ | 「〜⁉」「〜ってどんなところ？」 | タイトル・見出しに多用 |
| ♡ ♪ ☺️ ☔ ◎ ★ | 「〜です♡」「〜☺️」 | 1セクションに1〜2個程度 |
| (^^)/ (^^♪ | 「〜してみてください(^^)/」 | 段落末でアクセントに |
| ?♀️ ?️ ? | 絵文字置換が崩れて`?`になるケースも。**公開前にエンコード確認** | 多用しすぎ注意 |

**注意**: 顔文字・絵文字は **乱用しない**。1記事で計5〜10個程度が目安。それ以上はギャル風になりすぎる。

### 4-5. 文の長さとリズム

- **1文は40〜80文字** が読みやすい。100文字超は2文に分割。
- **改行をこまめに**。WP上で `<br>` を頻繁に入れる。1段落2〜3行で改行する慣習あり。
- **箇条書きを活用**: 3つ以上並ぶ情報は必ず `・` または番号付きリストに。
- **体言止め** も適度に混ぜてテンポを作る（多用しすぎ注意）。

### 4-6. 数字・固有名詞の表記

- **半角数字** を基本（「2025年8月14日」「6,300円」「30〜40分」）。
- **金額は ¥ または 円**。「¥6,900円」のように両方付ける表記もあり（過去記事に準拠）。
- **時刻はコロン**:「10:00〜20:00」
- **〜（チルダ）** で範囲を表す:「30〜40分」「2〜3度繰り返し」
- **ブランド名・店舗名は正式表記**。初出は正式名、2回目以降は通称OK（例: 初出「AMAM DACOTAN（アマムダコタン）」、以降「アマムダコタン」）

### 4-7. やってはいけない文体

- ❌ **常体だけで書く**（硬すぎる）
- ❌ **「である」「〜だ」連発**
- ❌ **絵文字ゼロ**（無機質に見える）
- ❌ **過度な敬語**（「〜でございます」「お客様」など）
- ❌ **批判だけで終わる**（辛口レビューでも必ず「でも○○な人にはおすすめ」と着地）
- ❌ **PR感丸出しの宣伝口調**（「絶対買い！」を強要するような表現）
- ❌ **専門用語の解説なし**（PCカラー、骨格診断などはサッと一言補足を入れる）

## 5. 画像のルール

### 5-1. 必要枚数の目安

| 記事タイプ | 画像枚数の目安 |
|---|---|
| A 完全ガイド型 | 15〜25枚 |
| B 商品レビュー型 | 10〜20枚 |
| C スポット紹介型 | 各スポット2〜3枚 ×店舗数 |
| D イベントレポ型 | 15〜30枚 |
| E マイバッグ型 | 全体写真 + 中身写真 計10〜15枚 |
| F Q&A・OB訪問 | 5〜10枚（時間帯ごとに1枚など） |
| G LOOKBOOK | コーデ全身×7〜10枚 + 詳細カット |

### 5-2. 画像の撮り方ガイド

- **アイキャッチ（OGP画像）**: 1:1（1080×1080）の正方形がベスト。商品名/タイトルが入った「表紙画像」をCanva等で作るパターンが多い。
- **本文画像**: スマホ縦撮りで構わない。横位置・縦位置を混ぜると単調にならない。
- **必ず光のある場所で撮る**。暗い場所はホワイトバランス調整 or 加工で明るく。
- **商品の全体カット + 寄りカット** をセットで。
- **ロケ写真**: 看板・外観・店内・商品 の4点セットを意識。
- **コーデ写真**: 全身 + 上半身 + 小物寄り を1セット。

### 5-3. キャプション

- 画像の **すぐ下に1行のキャプション** を置くのが慣習。
- alt textには **商品名・場所名・状況** を入れる（SEO観点でも必須）。
- WPでは「キャプション」フィールドに記入すると自動で `<figcaption>` 出力される。
- 画像SEOの詳細ルール（ファイル名・alt text・サイズ・WebP・lazy load）は §13-8 を参照。

```
[画像]
アマムダコタン　クロックムッシュ ← キャプション
```

### 5-4. 画像の権利・注意点

- **公式画像を使う場合は必ず転載許可を取る**。プレスリリース素材は要クレジット表記。
- **他人が写り込んだ写真は加工**（モザイク or 顔隠し）。撮影禁止エリアでの撮影はしない。
- **商品の値札・他客の所持品** が映り込まないように注意。
- **スクリーンショット**（公式サイト等）は引用ルールに従い、必ず出典URLを併記。

## 6. 必須情報の埋め込みルール

### 6-1. 店舗・施設情報の書き方

```
【店舗情報】
amam dacotan 表参道店（アマム ダコタン）
お問い合わせ 03-3498-2456
住所 東京都港区北青山3-7-6
交通手段 東京メトロ半蔵門線 表参道駅B2出口から徒歩1分
営業時間 11:00〜19:00　日曜営業
```

または、より簡潔に:

```
**住所：** 東京都渋谷区神宮前6-12-22
**営業時間：** 10:00〜20:00（年中無休）
```

### 6-2. リンクの貼り方

- **公式サイトリンク**は記事中盤と末尾の2箇所に配置（離脱を促しすぎないため）。
- リンクテキストは「[ブランド名] 公式ホームページ」「[商品名]公式販売ページ」のように **何のリンクか分かる文字列** にする。`こちら` 単体は避ける。
- **アフィリエイトリンク**（楽天・Amazon等）を貼る場合は、ASP/案件のガイドラインに従いつつ「※アフィリエイトリンクを含みます」表記を付ける（媒体ルールに依存。要確認）。

### 6-3. ハッシュタグ・SNS連携

- 記事末尾に Instagram プロフィールURLを貼る慣習あり。
- 関連投稿のIGリンクを本文中に差し込むこともOK。

## 7. WordPress入稿フロー

### 7-1. 入稿前の準備

- [ ] 原稿（テキスト）を確定（Notion / Googleドキュメント等で完成形にしてからWP入力）
- [ ] 画像をすべて準備（リネーム: `2026-04-amam-01.jpg` のような命名規則推奨）
- [ ] 画像サイズを最適化（WPアップロード前に長辺1500px・JPG 80%品質程度に圧縮。TinyPNG等）
- [ ] alt text・キャプションを画像ごとにメモ
- [ ] アイキャッチ画像（1080×1080）を別途作成
- [ ] 公開日・カテゴリ・タグを決めておく

### 7-2. WordPress側の操作手順

> ※ログイン情報は別途共有予定。実際の管理画面構成を確認後、本セクションを更新する。

1. **新規投稿** → 「ブログ記事」テンプレートを選択
2. **タイトル**を入力（§2のフォーマットに従う）
3. **本文**を入力
   - ブロックエディタ（Gutenberg）の場合：見出しブロック、画像ブロック、リストブロックを使い分け
   - クラシックエディタの場合：ビジュアル/テキストを切り替えながらHTMLも確認
4. **画像挿入**
   - メディアライブラリにまとめてアップロード
   - 各画像にalt text・キャプション入力
   - サイズは「フルサイズ」または「大」を選択（横幅は自動調整）
5. **アイキャッチ画像**を設定（記事一覧・OGPに使われる）
6. **カテゴリ**: ファッション部 / ビューティー部 / グルメ＆ライフ部 / エンタメ部 のいずれか1つ
7. **タグ**: 商品名・店舗名・地名・モデル名など5〜10個
8. **URLスラッグ**: 英数字のみ、内容が分かるもの（例: `amam-dacotan-review-2026`）
9. **メタディスクリプション** (SEOプラグインに項目あれば): 80〜120文字でリード文を要約

## 13. SEO規定・実装ルール

nonno.hpplus.jpは高いドメインオーソリティを持つ媒体だが、記事単体の最適化を怠れば検索上位は取れない。以下は「最低限守るルール」と「上位を狙うための加点要素」をセットで整理。**新規記事を書く前に §13-1〜13-2 を必ず実施**してから本文執筆に入る。

### 13-1. 記事執筆前の検索意図リサーチ（着手前必須）

- 記事を書き始める前に **必ずGoogle検索で対象キーワードを調べる**
- 上位10記事のタイトル・見出し・文字数を表にまとめる
- ラッコキーワード / Google サジェスト / 関連検索ワード で関連語を洗い出す
- 検索意図を以下4分類のどれに位置付けるか決める:

| 検索意図 | 例 | 記事タイプ |
|---|---|---|
| Know（知りたい） | 「ハリポタショップ 原宿 とは」 | A 完全ガイド型 |
| Go（行きたい） | 「アマムダコタン アクセス」 | C スポット紹介型 |
| Do（やりたい） | 「マグネットネイル やり方」 | B 商品レビュー型 |
| Buy（買いたい） | 「3coins ネイル レビュー」 | B 商品レビュー型 |

### 13-2. メインキーワード・サブキーワード設計

- **メインキーワード1個 + サブキーワード3〜5個** を必ず設計（執筆前にメモ）
- メインKWは「タイトル前半 + H1 + リード + URL + メタディスク」に必ず入れる
- サブKWは「H2見出し + 本文中」に自然に分散
- **キーワードスタッフィング（過剰詰め込み）は逆効果**。同じ語の連続出現は避ける

**例：「【完全ガイド】ハリー・ポッターショップ原宿店」**
- メインKW: `ハリーポッターショップ 原宿`
- サブKW: `予約方法` / `アクセス` / `エリア紹介` / `お土産` / `営業時間`
- 共起語: `魔法` `ホグワーツ` `ローブ` `4寮` `バタービール` `ニフラー`

### 13-3. タイトル最適化（SEO観点）

§2の基本ルールに以下を追加:

- **メインキーワードは前半20文字以内に必ず含める**（Google検索結果は約32文字で見切れる）
- **【】の中身もCTRに効く**:「完全ガイド」「最新」「2026」「保存版」「徹底」「知らないと損」
- **数字を入れる**:「10選」「100選」「7days」「500円で」など具体性で CTR 向上
- **感情ワード**:「徹底」「完全」「失敗しない」「正直レポ」「辛口」
- **NGパターン**: 抽象語のみ・キーワードが末尾・記号の連続（「！！！」）

### 13-4. メタディスクリプション

- WPでは「抜粋（Excerpt）」 or SEOプラグイン（Yoast / All in One SEO / Rank Math 等）の専用欄に入力
- **80〜120文字**で記事内容を要約
- メインKW + サブKW1〜2個を自然に含める
- **リード文と完全一致させない**（独自に書く）
- 「行動を促す」CTA一文を入れる:「〜が気になる方は要チェック」「実際に行ってきたレポをまとめました」

**テンプレ**:
```
[トピック/対象] を [具体的な切り口] でまとめました。[期待値: 読むと何が分かるか]。[CTA]
```

### 13-5. URLスラッグ

- **必ず英数字のみ**。日本語URLはエンコードで長くなりSNS共有時にも崩れる
- メインキーワードを英語にして組み込む
- 単語はハイフン（`-`）区切り、アンダースコア（`_`）非推奨
- 短く：3〜5単語、40文字以内
- 数字（年月）は将来更新時に矛盾するので **入れすぎ注意**

| 良い例 | 悪い例 |
|---|---|
| `harrypotter-harajuku-guide` | `%E3%83%8F%E3%83%AA...`（日本語URL） |
| `amam-dacotan-review` | `post-12345`（自動採番のみ） |
| `3coins-magnet-nail` | `3coins-magnet-nail-2023-summer-very-detailed`（冗長） |

### 13-6. 見出し構造（Hタグの使い方）

- **H1は1記事につき1個のみ**（タイトル）。WPテンプレで自動的にH1なら本文にH1を追加しない
- **H2 → H3 → H4 の順序を飛ばさない**（H2の次にH4はNG）
- **H2見出しはサブキーワードを必ず1つ含める**:「アクセス方法」「予約方法」「営業時間」など検索される語そのものを使う
- **見出しだけで全体像が分かるか** を必ず確認（目次のサイトリンクに採用されやすい）
- **疑問形の見出し** は「People Also Ask（他の人はこちらも質問）」に拾われやすい:「アマムダコタンとは？」「予約方法は？」

### 13-7. キーワードの本文配置

| 場所 | メインKWの登場目安 |
|---|---|
| タイトル | 1回（必須・前半20文字以内） |
| リード文（最初の100文字以内） | 1〜2回 |
| H2見出し | 全H2の30〜50%に含める |
| 本文 | 全体で5〜10回（自然な範囲） |
| まとめセクション | 1回 |
| alt text | 関連画像に2〜3回 |

- **キーワード密度は2〜4%が自然**。10%超でペナルティ対象
- **同じ語の連続出現は避ける**:「ハリポタショップ原宿店」を毎段落使わず「同店」「こちらの店舗」「原宿店」など言い換え
- **共起語を意識的に使う**（§13-16）

### 13-8. 画像SEO

§5の画像ルールに以下を追加:

- **ファイル名は英数字でキーワード入り**: ❌ `IMG_3947.jpg` → ✅ `harrypotter-harajuku-entrance.jpg`
- **alt textはキーワード+説明**: ❌ `alt="店内"` → ✅ `alt="ハリーポッターショップ原宿店の店内入り口"`
- **画像サイズは長辺1500px以下に圧縮**: TinyPNG / Squoosh で50〜80%圧縮
- **WebP化** を検討（WPプラグインで自動変換）。LCP改善に効果大
- **width / height 属性を必ず指定**: CLS（Cumulative Layout Shift）対策
- **遅延読み込み（lazy load）**: WPデフォルトで有効。ただしファーストビュー画像は `loading="eager"` に
- **アイキャッチは2サイズ用意**:
  - 一覧表示用 1080×1080（1:1）
  - OGP用 1200×630（1.91:1）

### 13-9. 内部リンク（最重要）

- **1記事あたり関連記事への内部リンクを3〜5本** 配置
- リンクテキストは「**こちら**」単体ではなく、**リンク先の記事タイトル or キーワード**:
  - ❌ `詳細は[こちら](url)`
  - ✅ `[ハリポタスタジオツアー東京の完全攻略はこちら](url)`
- **関連記事ブロックは本文中盤と末尾の2箇所** に配置するとSEO効果UP
- **過去記事からの被リンクも意識**: 新記事を書いたら関連する過去記事を編集して、新記事へのリンクを追加（一方向ではなく相互リンク）
- カテゴリ内回遊を意識：同じ「エンタメ部」「ビューティー部」内の関連記事へ誘導

### 13-10. 外部リンク・rel属性

- **公式サイトへのリンクは積極的に**（信頼性シグナル）
- ただし離脱しすぎないよう `target="_blank"` で新規タブ
- **PR記事・アフィリエイトリンクは `rel="sponsored"`**: ステマ規制 + Googleガイドライン両対応
- **信頼性が不明な外部サイトには `rel="nofollow"`**
- **過剰な外部リンクは避ける**: 1記事5〜10本までを目安

### 13-11. 構造化データ（Schema.org）

WPプラグイン（Yoast SEO / Rank Math / Schema Pro等）で自動付与されるが、記事タイプに応じて以下を意識:

| 記事タイプ | 推奨スキーマ | 効果 |
|---|---|---|
| A 完全ガイド | `Article` + `BreadcrumbList` | 基本表示の最適化 |
| B 商品レビュー | `Article` + `Review` + `Product` | 星評価のリッチリザルト |
| C スポット紹介 | `Article` + `LocalBusiness` | ナレッジパネル候補 |
| D イベントレポ | `Article` + `Event` | イベント情報カード |
| F Q&A | `Article` + `FAQPage` | FAQリッチリザルト |

- **FAQPage スキーマは Q&A型記事で必須**: 検索結果上にQ&Aがアコーディオン表示される
- **Review スキーマで星評価**: §3-6 の★5段階評価を構造化データに反映するとリッチリザルト対象
- 入稿後は **リッチリザルトテスト**（search.google.com/test/rich-results）で必ず検証

### 13-12. E-E-A-T（経験・専門性・権威性・信頼性）

Googleが特に重視する評価軸。**実体験ベース記事はnon-noエディターズの強み**なので最大限活用する。

- **取材日・撮影日を明記**:「2025年8月16日（土）取材」「2026年4月14日開催」
- **「実際に行ってきました」「実際に試しました」を冒頭で明示**
- **一次情報の証拠を残す**: 撮影写真・整理券・領収書（個人情報マスキング）など
- **著者プロフィールの充実**: §10のプロフィール枠を必ず表示。SNSアカウント・経歴も
- **引用元の明示**: 公式HPからの転載は「以下ホームページ参照」と明記し、URLを併記
- **更新日の表示**:「2023.08.31 更新日：2023.09.01」のように両方明記
- **YMYL領域（医療・金融）は専門家監修を入れる**: スキンケア・サプリ等は美容皮膚科医監修クレジット必須

### 13-13. Core Web Vitals / モバイル対応

| 指標 | 目標 | 主な対策 |
|---|---|---|
| **LCP**（最大コンテンツ表示） | 2.5秒以内 | アイキャッチ画像の最適化・eager読み込み・CDN |
| **INP**（インタラクション応答） | 200ms以内 | 重いJSプラグインの削減 |
| **CLS**（レイアウトずれ） | 0.1以下 | 画像のwidth/height指定・広告枠の固定サイズ確保 |

- スマホ閲覧率が80%超の媒体なので、**スマホ表示の改行・段落の見え方を必ず確認**
- 表（テーブル）は **3列以内** に抑える。それ以上は横スクロールで読みづらい
- フォントサイズは16px以上を維持
- 計測ツール: PageSpeed Insights / Chrome Lighthouse / Search Console「ウェブに関する主な指標」

### 13-14. リライト・更新運用

- **公開後3ヶ月で順位チェック**（Googleサーチコンソール）
- 検索順位が10〜30位で停滞している記事は **リライト** で改善
- リライト時のチェック項目:
  - [ ] タイトルにキーワード入っているか
  - [ ] 検索意図に答えられているか（足りない情報はないか）
  - [ ] 上位記事と比較して情報量・画像数が足りているか
  - [ ] 内部リンクを増やせるか
  - [ ] 画像を追加・差し替えできるか
  - [ ] 古い情報（営業時間・価格・スタッフ情報・年号）を更新したか
- **更新日を必ず更新**: WPで「更新日」が表示されるテンプレなら、Googleの鮮度シグナルに効く
- 大幅リライトでも **記事URLは変えない**（被リンク・順位が失われる）。URL変更時は301リダイレクト必須

### 13-15. 季節性・トレンドキーワード

- **年号入りタイトル**:「2026最新」「2026春」「2026年版」
- 古くなると逆効果なので、**毎年リライト** で年号更新
- **季節イベントは2〜4週間前に公開**: クリスマス記事は11月中、夏フェスは6月初旬
- **新商品・新店舗オープン直後が勝負**: オープン1週間以内に記事化すると独自情報として上位を取りやすい（ニュースクエリで指名検索が立ち上がる前に押さえる）

### 13-16. 共起語・関連語の活用

メインキーワードと一緒に頻出する語を本文に含めると、Googleが「網羅性が高い」と判断する。

**例: メインKW「ハリポタショップ 原宿」の共起語**:
> ホグワーツ / ローブ / 杖 / 寮 / 4寮 / グリフィンドール / スリザリン / 魔法動物 / バタービール / ハニーデュークス / ニフラー / ドビー / ミナリマ / 蛙チョコ / 整理券 / QRコード / アクセス / 神宮前

**共起語の調べ方**:
- ラッコキーワード「共起語」機能（無料）
- Googleで対象KWを検索 → 上位10記事に頻出する語を拾う
- 検索結果下部の「関連する検索キーワード」
- サジェスト（検索窓に入力した時の予測候補）

### 13-17. OGP・SNS最適化

- **OGP画像**: 1200×630px（1.91:1）必須。1:1のアイキャッチとは別に用意推奨
- **og:title** はSEOタイトルと変えてもOK（SNSでクリックされやすい煽り目に）
- **og:description** はメタディスクリプションを流用 or 独自に
- **Twitter Card** は `summary_large_image` を選択
- **画像内の文字は中央寄せ・大きめ**: SNSのサムネで読める文字サイズに
- 公開直後に **Instagram / X で告知**: ソーシャルシグナルでクローラ巡回が早くなる
- **OGPデバッガ** で公開前に表示確認:
  - Facebook: developers.facebook.com/tools/debug/
  - X: cards-dev.twitter.com/validator（旧）/ 投稿前のプレビュー

### 13-18. 内部競合（カニバリゼーション）回避

- **同じキーワードを狙う記事を複数書かない**
- 既存記事と被るテーマは、**既存記事のリライト** or **明確な差別化**
  - 例: 過去「ハリポタショップ赤坂店」あり → 新規は「原宿店」で完全分離
- **カニバリチェック**: `site:nonno.hpplus.jp [メインKW]` で同サイト内の検索結果を確認
- 競合する記事が複数ある場合は、片方を別キーワードに振るか、統合して片方を301リダイレクト

## 14. SEO重点チェックリスト（§8の補完）

§8の公開前チェックに加えて、SEO観点で以下を必ず確認:

### 14-1. キーワード関連
- [ ] メインキーワードがタイトル前半20文字以内に入っているか
- [ ] メインキーワードが H1 + リード100文字以内 + 複数H2 + まとめ に登場するか
- [ ] サブキーワード3〜5個がH2/H3に分散されているか
- [ ] キーワード密度が2〜4%に収まっているか
- [ ] 共起語が10語以上自然に登場しているか

### 14-2. 構造関連
- [ ] H1は1個のみか
- [ ] H2 → H3 → H4 の順序を飛ばしていないか
- [ ] H2見出しだけ読んで記事の全体像が分かるか
- [ ] 目次（Index）が設置されているか
- [ ] 疑問形のH2/H3が少なくとも1つあるか（FAQ・PAA対策）

### 14-3. メタ情報
- [ ] メタディスクリプション 80〜120文字
- [ ] URLスラッグが英数字・40文字以内
- [ ] アイキャッチ画像（1:1）とOGP画像（1.91:1）の両方設定済み
- [ ] og:title / og:description / Twitter Card 設定

### 14-4. 画像
- [ ] 全画像のファイル名が英数字でキーワード入り
- [ ] 全画像にalt text（キーワード+説明）
- [ ] 画像サイズ長辺1500px以下に圧縮済み
- [ ] width/height 属性指定済み
- [ ] アイキャッチ画像に `loading="eager"`
- [ ] それ以外は `loading="lazy"`

### 14-5. リンク
- [ ] 内部リンク3〜5本（関連過去記事へ）
- [ ] リンクテキストがキーワード or 記事タイトル（「こちら」単体は0個）
- [ ] 外部リンクが新規タブで開く
- [ ] PR記事の場合 `rel="sponsored"` 設定
- [ ] 関連過去記事からも新記事へリンクを追加した（相互リンク）

### 14-6. E-E-A-T
- [ ] 取材日・撮影日が記事内に明記されているか
- [ ] 「実際に行ってきました」等、一次体験が冒頭で示されているか
- [ ] 著者プロフィール枠が表示されているか
- [ ] 公開日 + 更新日が両方表示されているか
- [ ] 引用元URLが本文中に貼られているか
- [ ] YMYL領域なら専門家監修クレジットがあるか

### 14-7. 構造化データ
- [ ] Article schema 自動付与されているか（SEOプラグインで確認）
- [ ] 記事タイプに応じた追加schema（Review / Event / LocalBusiness / FAQPage）
- [ ] リッチリザルトテストで警告なし

### 14-8. パフォーマンス
- [ ] PageSpeed Insights で LCP 2.5秒以内 / CLS 0.1以下
- [ ] スマホ表示で改行・段落が崩れていないか
- [ ] テーブルが横スクロールしていないか

### 14-9. 公開後アクション（24時間以内）
- [ ] Search Console で「URL検査」→ インデックス登録リクエスト
- [ ] SNSで公開告知（X / Instagram）
- [ ] OGPがSNSで正しく表示されているか確認
- [ ] 関連過去記事から新記事への内部リンク追加

### 14-10. 公開後モニタリング
- [ ] 公開後7日でインデックス確認（`site:` 検索）
- [ ] 公開後30日でSearch Consoleの順位・CTR確認
